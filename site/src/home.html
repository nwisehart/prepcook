The method

What makes it different

Reproduce first

A bug card's Plan stage makes the failure happen, and only then explains it. The planning agent is told not to read code for the cause until it has a script that fails for the reported reason.

Reproduce first

The RCA and the knowledge graph

Every bug RCA goes into a knowledge store, linked into a graph of product areas, components and root-cause classes, so a cause that keeps coming back becomes visible and opens a pattern review of its own.

The knowledge store and the graph

Fresh-eyes review

A separate agent reviews the change in a fresh worktree, with the diff, the code around it and the reproduction, and none of the planning context. Its findings go back to the implementing agent for up to three rounds.

The independent review

Works alongside people

In Chef mode it works your tickets and you move the cards and approve each plan; in Prep mode it works on its own. An engineer who assigns a ticket to themselves takes it over, and Prepcook steps aside.

Working alongside people

Investigations and incidents

An investigation card runs Plan exactly as a bug does, then posts a triage report and stops until a person converts it to a bug or closes it. In incidents mode, each open incident becomes one, and the report goes back to the incident as a note.

Investigations Incidents

Integrations as factories

Notifications, ticketing, reproduction, evidence and agents are each configured under Settings → Integrations, rendered from what each provider says about itself, with a Test connection button per provider.

The Slack agent

Tammy

If Prepcook is the prep cook, Tammy is the waitress. When a customer reports something that looks broken, she takes the order to the kitchen: she asks the questions an engineer would ask, files an investigation card on Prepcook, waits for its triage report, and explains it to the customer in plain English.

The board image

prepcook up runs the board from the published image ghcr.io/nwisehart/prepcook-board:<version>, the version of the prepcook binary that starts it; there is nothing to pull by hand. To run the board elsewhere, see crates/remote/README.md; to build from a checkout, see Build, run and test.
